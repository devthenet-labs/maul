// WHAT IT DOES

Intents

Plans you approve. Builds you can watch.

Label an issue and a read-only agent posts its plan on the issue, word for word. Approve it, and a second agent builds exactly that plan in a sandboxed pod running your repository's own toolchain image, then pushes a branch and opens the pull request.

  • Watch the live command output and the agent's conversation as it works.
  • Every run has a wall clock, a turn limit and a cost budget you set per project.
  • Multi-repository changes get one plan and a pull request per repository.
Enable intents →
Previews

A live URL for every pull request.

Each intent's pull request is deployed into an isolated preview slot until it merges or closes. The link lands on the issue and the pull request, so reviewers click instead of checking out a branch.

  • Optional sign-in in front of every preview, checked against your cluster's RBAC.
  • Several repositories, path-routed on one host.
  • maul setup previews writes and applies the whole configuration.
Set up previews →
Security fixes

Alerts in. Fixes out. The rest handed to a human.

Code scanning, Wiz, Google Security Command Center or any HTTP source: related alerts gather into one Finding with one tracking issue. An agent investigates each; false positives are dismissed, confident fixes become pull requests in priority order, and everything else goes to the owner.

  • Ownership and infrastructure context arrives before the agent decides.
  • Approve, retry, expedite or suspend from the issue, the status page or the CLI.
How findings flow →
Usage

Know what every run costs.

Model traffic goes through maul's egress broker, so tokens are metered where they are spent — per person, per project, per run — and priced. Budgets stop a run before it overspends.

  • People can bring their own model credential; their runs use it.
  • maul get usage gives the same report in the terminal.

// THE TRUST MODEL

Automation with edges you can see.

Nothing to steal in the pod

Claude and Codex pods hold no credential at all. Model traffic goes through an in-cluster broker that adds the key on the way out; the agent never talks to GitHub.

A human at both ends

A person approves every intent's plan before anything is built, and a person merges every pull request. Maul opens them; people decide.

The cluster is the database

Custom resources carry all state. No shadow database, no queue to run — back it up, audit it and query it with the Kubernetes tools you already have.

Fenced in by default

The repository arrives as a digest-verified tarball, egress is denied, and dependency access is an explicit, per-repository network profile.

// SMALL BINARIES, ONE SYSTEM

Separate concerns. One source of truth.

Each component owns a narrow set of state transitions, and the optional ones stay off until you turn them on.
